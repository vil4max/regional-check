# Release 3.3

Marketing version 3.3.0. Two changes: a CarPlay Status screen that reads at one glance (merged,
TestFlight round `tf-3.3.0-1`) and an optional all-clear notification
([ALLCLEAR-push](../../../specs/ALLCLEAR-push/spec.md), [REQ-PUSH](../../requirements/push.md)).
The user-facing changes are in [CHANGELOG.md](../../../CHANGELOG.md).

The agent prepares these texts and the tag; every App Store Connect step is the owner's.

## Owner steps

1. **App ID:** in the Apple Developer portal, Certificates, Identifiers & Profiles, Identifiers,
   open `vil4max.RegionalCheck`, enable **Push Notifications**, save. The entitlement `aps-environment`
   is in `RegionalCheck.entitlements`; Xcode Cloud's managed signing needs the capability on the
   App ID, and a build without it fails to sign. The widget target needs nothing.
2. **APNs key:** create an APNs authentication key (Keys, Apple Push Notifications service), keep
   the `.p8` file, the Key ID and the Team ID (`BTHRDS7254`), and store the key as a secret of the
   server himself; the agent never handles it.
3. **App Privacy:** in App Store Connect, App Privacy, add the answers in the table below.
4. **TestFlight:** after the push PR is merged, `ci_scripts/tf-check.sh origin/main` prints the tag
   command for `tf-3.3.0-2`. Paste "What to Test" below into the build.
5. **Submit** (later, after a real push is seen): create version 3.3.0, select the build, paste
   What's New, replace the review notes paragraph, update the description sentence, and submit.

## App Privacy answers

The privacy manifest declares the same data (`PrivacyInfo.xcprivacy`). None is linked to identity
and none is used for tracking.

| Data type | Collected | Linked to the user | Used for tracking | Purpose |
|---|---|---|---|---|
| Coarse Location (the region name) | Yes, only if the all-clear notification is on | No | No | App Functionality |
| Device ID (the push token) | Yes, only if the all-clear notification is on | No | No | App Functionality |
| Precise Location | As before (processed for the region lookup) | No | No | App Functionality |

Privacy Policy: [docs/privacy-policy.html](../../privacy-policy.html), "All-clear notification
(optional)"; publish the same text at the Privacy Policy URL on vil4max.com before submitting.

## App Review notes

Add this paragraph to the notes kept from 3.2:

```
Notifications: version 3.3.0 adds an optional "Notify me when the alert ends" switch on the Details tab (off by default). Switching it on asks for notification permission and sends the device's push token, the last region the app saw, the language and the build environment to our server (drivecheck.vil4max.com), so we can send one notification when the alert in that region ends. Nothing else is pushed (no alert-start notices, no marketing). Switching it off, or turning notifications off in iOS Settings, deletes the token from the server. The notification is free; no purchase is involved. To see the switch: open Details and scroll to "All-clear notice".
```
