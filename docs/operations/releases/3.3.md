# Release 3.3

Marketing version 3.3.0. Two changes: a CarPlay Status screen that reads at one glance (merged,
TestFlight round `tf-3.3.0-1`) and an optional all-clear notification
([ALLCLEAR-push](../../../specs/ALLCLEAR-push/spec.md), [REQ-PUSH](../../requirements/push.md)).
The user-facing changes are in [CHANGELOG.md](../../../CHANGELOG.md).

The agent prepares these texts and the tag; every App Store Connect step is the owner's.

## Owner steps

1. **App ID:** in the Apple Developer portal, Certificates, Identifiers & Profiles, Identifiers,
   open `vil4max.RegionalCheck`, enable **Push Notifications**, save. The entitlement `aps-environment`
   is in `RegionalCheck.entitlements`; Xcode Cloud's managed signing needs the capability on the
   App ID, and a build without it fails to sign. The widget target needs nothing.
2. **APNs key:** create an APNs authentication key (Keys, Apple Push Notifications service), keep
   the `.p8` file, the Key ID and the Team ID (`BTHRDS7254`), and store the key as a secret of the
   server himself; the agent never handles it.
3. **App Privacy:** in App Store Connect, App Privacy, add the answers in the table below.
4. **TestFlight:** after the push PR is merged, `ci_scripts/tf-check.sh origin/main` prints the tag
   command for `tf-3.3.0-2`. Paste "What to Test" below into the build.
5. **Submit** (later, after a real push is seen): create version 3.3.0, select the build, paste
   What's New, replace the review notes paragraph, update the description sentence, and submit.

## 3.3.1

Marketing version 3.3.1, a fix-only release ([BUG-LA-push-start](../../../specs/BUG-LA-push-start/spec.md)).
In 3.3.0 the server never started the Live Activity by push: it refused the app's 256-digit
push-to-start token (measured on a simulator) because it accepted at most 200 hex digits. The fix is
on the server (drivecheck-api #10, deployed 2026-11-12) and reaches 3.3.0 installs too; 3.3.1 adds
the device-log diagnostics that confirm it. TestFlight round `tf-3.3.1-1` is build 130.

### Before submitting

1. Device check (plan T010): with build 130 installed and opened once, an alert in your region shows
   the red Live Activity on the Lock Screen and on the CarPlay Dashboard without opening the app,
   and it ends green at the all-clear. Until that is seen, the What's New below is a claim, not a
   fact: do not submit.
2. App Privacy, the privacy policy and the review notes need no change: 3.3.1 collects nothing new.
3. Submit 3.3.1 with build 130 (the owner's step), then tag `v3.3.1` on `5ac410c`.

Submitted for App Review on 2026-11-12 at about 18:03 (local), build 130, release option automatic
after approval, locales en-US, uk and ru as in 3.3.0. The device check was not done first: the
owner decided not to wait for an alert, which may not come ("Тревогу мы ждать не можем... Нужно
отправлять"). The What's New claim therefore rests on the simulator evidence until a device shows
